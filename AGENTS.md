# Notion workflow

Configure `NOTION_ROOT_PAGE` by page name, URL or UUID, then run `discover` before using content commands. Discovery manifests live in the git-ignored `.notion-discovery/` directory; never commit them. All commands are scoped to the configured root. Use `boards` to inspect available boards and live schemas; rerun discovery after changing roots or when schema validation asks for it. Never fall back to workspace-specific IDs or pick an ambiguous root/board.

Read `docs/notion/README.md` before interacting with the project's Notion workspace. When the user initiates work in the CLI and supplies a Notion board/page ID, read that entry and `sync` its comments, post concise start, blocker/question and completion milestones to the entry, and update its valid status when appropriate. Record substantive decisions in the Decision Register and regular documentation in the Document Hub; all content is Markdown (inline or `--file`), with Mermaid for diagrams. Feature Requests is read-only. Edit existing page content only with `page edit`: show the user the preview diff, and apply it with `--approve=<token>` only after they approve that exact change. These scripts operate only while invoked; Notion comments cannot wake this CLI, so process later feedback only when the user requests a sync. Never write to Product Roadmap without explicit user permission for the specific change, regardless of the CLI approval flag. Never copy credentials or sensitive logs into Notion.

# Agent toolkit

Read `docs/agent-toolkit/README.md` before using or switching the installed toolkit. Shared active skills are managed adapters in `.agents/skills/`; complete pinned upstream sources and local tool state live in ignored `.agent-toolkit/`. Never overwrite a modified/unmanaged skill or activate competing design directors. Use `node tools/agent-toolkit/toolkit.mjs profile list` and `profile use <name> [+pack ...]`, then reload/restart the host. Start with `using-superpowers` on hosts without the supported repo-local startup hook; namespaced `superpowers:<name>` references map to the shared skill `<name>`.

Superpowers is the normal process owner, not authority to bypass user approval. Default to inline execution; use subagents only when appropriate and authorized. When bunshin is explicitly selected, do not also start a competing Superpowers implementation loop. Preserve user changes (including when applying TDD); meaningful scope/behavior changes still need clarification. Keep plans in the session workspace unless repository plans are requested. Existing Notion edit/Roadmap approvals remain mandatory. No automatic cloud uploads, provider routing, paid generation, app instrumentation, global hooks or floating installers. Use the local tool launcher rather than changing system runtimes. Graphify is code-only by default; OmniRoute is unconnected, Reticle uninstrumented and Superdesign service use opt-in.

# Improving the tooling

When the same manual workaround or ad-hoc command comes up repeatedly — for example raw Notion API calls, inline `node -e` snippets, or multi-step sequences you keep re-typing — recommend a new command or an update to an existing tool in `docs/notion/` (or another small script) instead of repeating it. Also recommend one when a current command's limitations keep getting in the way. Describe the need, how often it came up, and the proposed interface, then ask the user before implementing. When a tool is added or changed, keep it cross-platform (Node, no shell-only wrappers), add tests to `docs/notion/notion.test.mjs`, and update `docs/notion/README.md` and this file. The `Notion scripts tests` workflow runs the tests on Linux and Windows.

Agent-toolkit-specific unit tests additionally live in `tools/agent-toolkit/toolkit.test.mjs`; the separate `Agent toolkit tests` workflow exercises profile safety without installing external runtimes. The Notion regression suite covers preservation of its credentials and sync state across profile changes.
